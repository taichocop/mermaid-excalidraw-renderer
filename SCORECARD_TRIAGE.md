These offsets identify the original findings, not offsets in the new candidate. Upstream paths below are pinned package files; the candidate keeps Excalidraw 0.18.1, converter 2.2.2 and Mermaid 11.17.2. Candidate plugin locations name current source functions. Build metadata distinguishes resolved inputs from emitted code.

Controlled browser probes use the production bundle, disposable diagrams and synthetic clipboard/file/storage sinks. They never access a real clipboard or existing browser storage. A pre-fix main build exposed PNG/SVG context actions and wrote twice to synthetic `writeText` (document copy and SVG action). Instrumented Function/WASM counts were 0/0 after render and 28/2 after that copy/action sequence. Those are aggregate calls during the sequence, not attribution of every call to SVG export, nor a scanner count. No storage/file-picker/external request was observed in that sequence. A synthetic empty file-launch environment registered one upstream consumer.

## Native adopted-parent repair — 2026-10-15

Native Obsidian 1.14.4 A/B compared BASE main `9e783b9f3738de2de4281a7b5b75ada7b24ff2f6` with PR #41's initial candidate `b4e6e1bd7186dac7acdfd6e80e810c5d153a51e6`. Modal content had secondary ownerDocument but main-realm prototype in both builds. BASE's `ownerDocument.createElement("div")` produced a secondary-realm viewer; direct `contentEl.createDiv()` produced a main-realm viewer adopted into that document. Matching ownerDocument alone did not establish equivalence. Secondary keyboard/focus/cleanup checks passed on both; the constructor-realm change was a separate regression.

Before source repair, three detached adopted-parent factories were compared in Native Obsidian and a Chrome fixture modeling the observed realm-bound helpers. Direct receiver `createDiv` retained main realm. An owner-document-created DocumentFragment's public `createDiv`, followed by explicit append, matched BASE's document factory: secondary ownerDocument, secondary HTMLDivElement instance, no main HTMLDivElement instance, correct parent. The fragment emptied after the move. This reuses the ownership pattern already used by LivePreview. Installed public Obsidian 1.13.1 typings declare the helper on Node, including DocumentFragment; no host/prototype patch is needed in production.

The production-bundle regression now opts into main-realm Modal construction followed by secondary-document adoption. Helpers are installed per fixture realm to model Native 1.14.4; ordinary foreign-document fixtures remain separate. The test exercises the actual DiagramPreviewModal.onOpen path, checks the adopted parent's main prototype and the viewer's secondary constructor, then retains viewer/root through refresh, replacement, Escape, Close and disable cleanup. It fails on the initial candidate's actual production bundle because viewerMainRealm is true. Repaired-candidate validation and Native production acceptance are recorded in [PR #41](https://github.com/taichocop/mermaid-excalidraw-renderer/pull/41), separately from the detached factory probes.

Classification: `DOCUMENT_FRAGMENT_CREATE_DIV`. Cross-window correctness takes priority over scanner cleanliness. The Native factory comparison proves realm equivalence of this strategy to BASE; production Native acceptance is a separate gate. No warning disappearance is claimed. A fresh Community Directory scan after a future published release remains required; Issue #16 stays open. README, CHANGELOG, versions, release assets, dependencies and permissions are unchanged.

### Pan cursor choice and ownership

Ordinary class specificity was measured against the real upstream canvas's inline `default`, `grab`, `pointer` and `crosshair` cursors; every computed cursor retained the inline value. The candidate therefore uses the public Obsidian `HTMLElement.setCssProps({ cursor: "grabbing" })` helper on the captured canvas, with no CSS change or new `!important`. Installed public typings declare this helper, and Obsidian 1.14.4's installed implementation delegates to `CSSStyleDeclaration.setProperty` without a priority argument.

Before taking ownership, standard CSSOM getters capture the original declaration's value and priority. Gesture completion restores them with CSSOM `setProperty` only if the declaration still equals the plugin's temporary `grabbing` with empty priority. An absent original declaration is removed, a pre-existing priority is preserved, and newer cursor updates are retained. The helper cannot express a priority, so CSSOM restoration preserves existing state without introducing a new priority. No viewer-external element, class, body style, global stylesheet or upstream private API is modified.
